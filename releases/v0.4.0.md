# Papo TUI 0.4.0

Papo TUI 0.4.0 adds file and clipboard attachments, pinned-message browsing,
server message search, a member drawer with profiles and member actions,
permission-aware controls and role-colored member names.
Notifications, pinned messages and search share an animated message-location
view, with faster navigation to older messages when their creation time is known.
These notes describe the changes since [0.3.1](v0.3.1.md).

## File attachments

Press **F5** in the editor or select **📎** beside the emoji button to choose
files. The system file dialog opens when available; otherwise, the application
opens a terminal picker. Canceling a system dialog cancels the selection.

The terminal picker accepts a directory or file in **Caminho** (Path). Use arrows
to browse, Enter to open a directory or mark a file, and Space to mark files.
Tab moves between the path, list, **Cancelar** (Cancel) and **Anexar** (Attach).
It remembers the last directory during the current conversation view.

Prepared files appear in a horizontal strip between history and the editor.
Select a file with Left/Right and press Enter, or click its **🗙**, to open
**Remover anexo?** (Remove attachment?). Removing an item affects the draft;
the original local file is kept. Long strips scroll to keep selection visible.

Press Enter in the editor to send the prepared files with optional message text.
Messages containing only files are supported. Selecting or pasting files never
sends them immediately. Tab follows the visible order of history, attachments,
editor, paperclip and emoji button; Shift+Tab reverses it. Left/Right switches
between the paperclip and emoji buttons when either has focus.

Attachment drafts are retained separately for each conversation during the
current run. Editing an existing message preserves the send draft; finish or
cancel editing before adding files. Files added while an earlier send is pending
remain in the draft after that send is confirmed. Signing out or quitting
discards unsent drafts.

### Clipboard files, screenshots and text

**Ctrl+V** reads copied local files, PNG/JPEG images such as screenshots, or text.
When several representations are offered, files take precedence over images,
then text, so one paste does not insert duplicate representations. Copied folders
and remote file URLs are excluded; a plain-text path remains text.

Windows uses its native clipboard. On Linux, file/image clipboard access uses
**wl-paste** from wl-clipboard on Wayland or **xclip** on X11. SSH sessions and
sandboxed environments without local clipboard access can use F5 for files and
the terminal's normal text paste command. A terminal that intercepts Ctrl+V
must forward that key to the application. The [usage guide](../docs/usage.md)
includes the Kitty mapping and setup instructions.

### Preparation, limits and retries

Files are copied privately in the background. Once preparation finishes, changing
the original does not alter the captured attachment. Drafts and manual retries
retain the prepared bytes. Read errors and insufficient temporary space produce
a notice without discarding already prepared files or text.

Client limits are **25 files per message**, **512 MiB** of temporary attachment
data across drafts and pending sends, and **64 MiB** per clipboard image. These
limits do not override the server's upload policy. Sending files requires both
attachment permission and permission to send in that conversation. Revoked
permission leaves prepared files in the draft.

Failed sends require an explicit retry with Ctrl+T. When the result is uncertain,
check history before confirming another attempt, which may duplicate a message.

## Pinned messages

Click **📌** (**🖈** in text mode) in the conversation header or press **F8** outside
the media player. The scrollable list supports arrows, PageUp/PageDown, Home/End
and the mouse wheel. Type in **Buscar** (Search) to filter loaded pins by message
text, author name or username, ignoring letter case. Ctrl+R refreshes the list.

Enter or a click opens message details. **Ir para mensagem** (Go to message)
locates the original in its conversation; **Desafixar** (Unpin) removes the pin
when permitted. Go to message is selected initially. Left/Right or Tab selects
an action, Enter activates it and Up/Down scrolls the preview. Esc returns to
the list while preserving its query and position.

The conversation context menu offers **Fixar mensagem** (Pin message) or
**Desafixar mensagem** (Unpin message) after pin state loads. Ctrl+R retries a
failed state lookup while the menu is open. Pin actions require the applicable
pin permission independently of permission to delete other people's messages.
The server allows at most **100 pinned messages per conversation**. Failed or
uncertain pin mutations are not repeated automatically; refresh before retrying.

## Server message search

Click **🔍** (Search) in the conversation header or press **F3**. Enter
message content and press Enter or activate Buscar to submit a server query.
Typing alone does not send requests. The initial scope is the current server,
ordered newest first. Matching follows the server's search behavior. Whole-server
search may omit DMs; choose a specific DM to search that conversation.

**Filtros** (Filters) opens a separate view in the same modal:

| Filter | Behavior |
| --- | --- |
| Autor (Author) | Choose a message author with a searchable name selector. |
| Conversa (Conversation) | Choose a channel or DM with a searchable selector. |
| Menciona (Mentions) | Choose the person mentioned in the message. |
| Contém link (Contains a link) | Require an HTTP/HTTPS URL in the content. |
| Data inicial / Data final (Start / end date) | Use YYYY-MM-DD; both boundary dates are included. |
| Anexos (Attachments) | Choose any, with attachments or without attachments. |
| Ordem (Order) | Choose newest or oldest first. |

Selectors include **Qualquer / limpar filtro** (Any / clear filter). Tab or
Up/Down reaches filter controls, with scrolling on smaller screens. **Aplicar**
(Apply) saves the filter draft; **Cancelar** (Cancel) or Esc discards its edits.
**Limpar filtros** (Clear filters) clears the draft. Applying filters returns to
results; execute Buscar to submit them. Empty text is accepted with at least one
filter; ordering alone is not a search criterion.

From the query field, Down reaches Buscar and Filtros, where Left/Right switches
buttons. Down again enters results; Up from the first result returns to the
buttons, then to the query. Tab/Shift+Tab also moves between these areas.

**Carregar mais** (Load more) requests another page. **Alterações pendentes**
(Pending changes) indicates that edited criteria must be submitted before more
results can be loaded. Ctrl+R repeats the current text and filters. A local bound
of **1,000 results or 4 MiB** produces a partial-list notice; refine the query to
continue. Enter or a click opens details and the shared Go to message action.

Searching and viewing previews do not open inactive histories or mark
notifications read. Explicitly opening a destination conversation has its normal
read behavior.

## Server members and profiles

Press **F10** or select **👤** beside pinned messages to open the right member
drawer. It reserves space on wide terminals and overlays the conversation on
narrow screens. Closing or resizing preserves the draft and reading position.
Each entry shows an avatar or centered first initial, nickname and a colored
presence dot with a text label. Unconfirmed presence appears as unknown.

Conversation footer hints include **F10 membros** (Members), shortened to
**F10** on compact layouts. Hints adapt to the available width.

Members are grouped by their first returned role by default, with one entry per
person; this display order does not imply a role hierarchy. Switch the grouping
control to group by online, away, busy, offline or unknown status. The grouping
choice is saved locally across runs and instances. Search with **/** or **Buscar**
(Search) by nickname or @username, ignoring case. Search covers loaded members;
loading and partial-list notices identify incomplete results.

Use arrows, Home/End or PageUp/PageDown to select members. Tab and Shift+Tab move
between search, grouping and results. **Ctrl+R** refreshes; Esc or F10 closes the
drawer. At the top of history, Up reaches the header controls **🔍**, **📌/🖈**
and **👤**. Left/Right switches controls, Enter opens one, and Down returns to
history or enters the open drawer from 👤. Tab also reaches these controls.

Press **m** on a member or right-click their row to open a compact context menu.
It appears to the left of the drawer, or above/below the selected row when space
is limited, keeping the name visible. Its available actions are:

- **Ver perfil** (View profile): show the banner, avatar, nickname, @username,
  roles, description, presence and status message when available. Enter on a
  member also opens the profile. Avatars and banners fit without cropping;
  scroll with arrows or the wheel, refresh with Ctrl+R and return with Esc.
- **Mensagem** (Message): open or reopen a DM and focus its editor.
- **Bloquear / Desbloquear** (Block / Unblock): show only the applicable action,
  without requiring an administrative role. Blocking prevents DMs in both
  directions while leaving public-channel messages visible.
- **Banir / Desbanir** (Ban / Unban): require the instance owner or confirmed
  **manage_server** permission and confirmation. Banning applies to the whole
  instance and revokes the target's sessions; unbanning requires a new sign-in.
- **Gerar link de reset de senha** (Generate password-reset link): require the
  same administrative permission and confirmation. The result shows a
  single-use link and expiration, with **Copiar** (Copy). A new link invalidates
  earlier links; closing the modal discards the displayed link.

Your own entry offers only the profile. Menus reuse the signed-in account's
existing permission state. Block state is prepared on drawer opening and ban
state comes from the member list. If these are still loading, a placeholder
updates automatically when actions are ready. Failed mutations require an
explicit retry; refresh uncertain results before deciding to repeat an action.
The server remains authoritative. Profile metadata can be refreshed with Ctrl+R.
Ultralight retains text and initials without acquiring member images.

## Direct messages

In the DM list, Up/Down selects a recipient and Enter or Right opens the
conversation. On wide screens, clicking a DM keeps focus in the list so arrows
continue selecting people; typing focuses the editor. Selection stays visible
even when recipients share a role color. Moving selection does not fetch
inactive conversation histories.

Press **m** on a selected DM or right-click its entry for **Fechar DM** (Close DM).
The menu keeps the recipient's name visible. Enter or a click closes the DM;
Esc or m dismisses the menu. **Ctrl+D** remains available in the list. Pending
sends must finish before closing. Closing preserves remote history, and a new
message can make the conversation reappear. Use a member's Message action to
start a new DM; F10 now opens the member drawer.

## Message location and notifications

Go to message from notifications, pinned messages and search keeps the modal open
with an animated **Localizando mensagem…** (Locating message…) view. The panel
closes when the destination is ready, making progress visible before the selected
message appears in history. Esc cancels and returns to details; failures remain
in the modal for an explicit retry.

For destinations with a known message creation time, cursor-based lookup avoids
walking every page between recent history and the target. Destinations whose
message time is unavailable retain the existing sequential lookup. Notification
event times are not substituted for message creation times.

The destination retains the existing highlighted border and centering while
surrounding content loads. Media outside the area covered by the modal remains
visible. The F9 footer label consistently identifies **notificações**
(notifications). Discovery shortcuts appear in the footer; **F3** opens search,
**F5** adds files and **F8** opens pins. F8 retains its media-properties action
inside the player.

Mention numbers are centered inside graphical notification badges, without the
extra **+** suffix. Counts still describe known mentions in loaded previews,
rather than a server-wide total.

## Permissions and channel access

The channel list hides conversations the account cannot read. Context menus
and keyboard shortcuts follow the account's available message actions.
Read-only channels still allow keeping a draft, editing or deleting one's own
messages, viewing reaction participants and removing one's own reaction.
Sending, replying and adding reactions require permission to send messages.
Administrative roles do not grant editing of another person's messages;
deleting them requires the applicable channel deletion permission. That
permission does not grant deletion of other people's DMs.

Role assignment and removal apply when their WebSocket events arrive, including
while a menu or confirmation is open. Other permission definitions are reconciled
every **30 seconds** in the active server tab and on Ctrl+R, with delays possible
during disconnection or rate limiting. Actions that need unconfirmed permissions
remain unavailable with a loading or retry notice.

Losing confirmed access closes the active channel history while preserving its
draft. When access returns, select the channel to resume. Pending actions still
waiting to be transmitted are canceled if permission is revoked; requests
already transmitted can finish. The server remains authoritative. Role, channel
and server administration screens are not included in this release.

## Role-colored member names

Member names use their assigned role color in history, member and mention lists,
message previews, notifications, search, reply previews and reaction participants.
The first valid color in membership order is used, with **white** as the default;
this display convention does not establish a role hierarchy. Assignment/removal
events update colors for other members as well as the signed-in account.
Terminals with indexed colors use the nearest supported approximation.

## Terminal window title

In terminals that support window titles, the title shows the current channel
and server, for example **geral | Comunidade**. Direct messages use
**DM com Bia | Comunidade**.

A suffix such as **(3)** shows the total known unread mentions across connected
instances, including mentions of you and `@everyone`. Ordinary unread messages
do not add to this count. The number updates as mentions arrive or are read,
including activity in another connected instance, and disappears at zero.
Switching conversations or renaming the active channel updates the title.

Returning to login or account management clears the conversation name.
Long names are shortened safely, and remote names cannot inject terminal
controls. A terminal setting that forces a fixed tab title may override this
display.

## Media viewer and embed covers

Pressing Enter on an embed cover that carries a video opens the video player
instead of the cover image. The **Abrir player** (Open player) entry keeps
working and reuses the download already made for the cover, so playing an embed
still costs no extra bandwidth.

While the image viewer is open, the left and right arrows move between the
images of the opened message when it carries more than one. The viewer shows the
current position, for example **2/3 · ←→ imagens** (images), wraps around, and
keeps the media properties panel open. Images belonging to other messages never
join the sequence.

## History and authentication fixes

Replies remain separate from adjacent messages when history groups consecutive
messages from the same author, preserving their reply context.

Private instance authorization identifies server-reported IP blocks rather than
attributing every HTTP 403 to the account. Other access refusals distinguish
instance authorization, account login and session validation.

## Builds and upgrade notes

The existing Linux and Windows package formats and x86_64/ARM64 targets remain
available through the release pipeline. Use the
[installation guide](../docs/installation.md) for package selection and the
[usage guide](../docs/usage.md) for controls and troubleshooting. This release
does not require a new third-party library. Linux clipboard image/file support
uses the optional helpers described above; native file selection depends on
the local desktop dialog service.

Native file dialogs are enabled by default. Source builds can pass
**-DPAPO_NATIVE_FILE_DIALOGS=OFF** to CMake to use the terminal picker directly.
Normal, Light and Ultralight retain their existing media behavior; attachments,
search, pins and permission controls are available independently of the selected
rendering mode.

Linux builds use **ncurses 6.6** consistently with development and Windows
builds, preserving text selection and copying during rapid mouse drags.

The installation guide now includes prerequisites for Fedora, RHEL, Arch Linux
and Windows. [BUILD.md](../BUILD.md) replaces CONTRIBUTING.md with the packages
and commands needed to compile Linux binaries and Windows executables, run tests
and prepare DEB, RPM, Arch, AppImage, Flatpak, Windows ZIP and installer packages.

## Release automation

Release runs are restricted to pushes that change **CMakeLists.txt** on **main**.
An actual version increase is required before creating a tag, building packages
or publishing. Changes to that file that retain the version skip those steps.
Pull requests run routine CI, titled **CI for PR #...** independently of the
pull request's title; release-mode builds reject other event/branch contexts.
Tag pushes and manual dispatches do not start the Release workflow. Failed
release jobs can be retried in their original main-push run.

## Release history maintenance

Future features, behavior changes and fixes affecting already released versions
are recorded in **releases/Unreleased.md**. Fixes made while a new feature is
still being developed are part of that feature's delivery rather than separate
release entries. Preparing a release consolidates the pending entries into its
complete notes and changelog and leaves Unreleased empty for the next cycle.
