# Papo TUI 0.3.1

This maintenance release adds PR-based release automation to the functionality
introduced in [Papo TUI 0.3.0](v0.3.0.md), including message interactions,
notification improvements, animated server emojis and keyboard shortcuts.

- Develop on the permanent `dev` branch and submit changes, including the
  version update, through a pull request targeting `main`.
- Run the existing routine CI checks on every PR update. A new commit cancels
  the previous run for that PR; version commits receive the same checks.
- Publish a release automatically after an increased version is merged into
  main. The workflow validates the changelog and notes, tags the merged commit,
  and builds and tests the native packages before publication.
- Reuse the validated package artifacts for upload, retaining the source
  archives and SHA256SUMS. Existing tags and published releases are preserved;
  failed builds can be retried using their original tag.
- Use English filenames for the [installation guide](../docs/installation.md)
  and [usage guide](../docs/usage.md), including installed documentation.

Merge permanent-dev pull requests with a merge commit, then synchronize main
back into dev before the next delivery. No direct commit to main is required
by the release automation. Application controls and the backend API contract
remain unchanged from 0.3.0.
