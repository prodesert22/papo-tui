# Papo TUI 0.2.0

This release adds display modes for terminals with different performance and
graphics capabilities.

## Application modes

Open **Configurações** (Settings) with F2 or the gear beside your name below
the channel list. In **Geral** (General), select a mode and choose **Salvar e
aplicar** (Save and apply). The selected mode is saved for future runs. Other
settings sections are placeholders and do not currently change the application.

- **Normal** uses Kitty, Sixel or iTerm2 graphics when supported and renders
  with Chafa when no graphics protocol is available. Animated GIFs and videos
  are enabled.
- **Light** renders images and animated GIFs with colored Chafa characters and
  uses native Unicode emojis. Video playback is disabled. Its media helper
  exits after three seconds without work; cached images remain available.
- **Ultralight** is text-only. It does not download or preview media and does
  not start the media helper. Attachments appear one per line with their type,
  name and size, without space reserved for images or avatars.

Chafa preserves RGB colors in truecolor terminals and uses the nearest
available colors in indexed-color terminals.

The media helper isolates image, animation, graphics and video libraries from
the TUI process. This reduces media memory use in Ultralight and releases the
helper's libraries after Light mode becomes idle. Existing images and animated
GIFs continue to use the current media cache. Video controls, multiline message
input, emoji suggestions and keyboard navigation retain their existing
behavior.

The release uses the existing service API and adds no backend requirements.
See the [usage guide](../docs/usage.md) for application controls.

CI shares dependency preparation between normal, sanitizer and coverage builds.
Release packaging runs independent Linux targets concurrently within each native
architecture runner, retaining the full test suites and package installation
checks. Dependency prefixes, Flatpak SDKs and source downloads are cached;
per-target logs and timings remain available when a build fails.

Windows packages include the GLib subprocess helpers required to start the
media helper with redirected pipes.

## Known issues and validation

Native Windows console input currently drops non-ASCII characters when read
through ncurses. This affects accented text and emojis, including usernames
such as `josé`. The Windows terminal Unicode tests are failing.

In CI run 38933950028, Linux release and coverage builds, Linux ARM64 and quality
checks passed. The Linux sanitizer build failed `input-controls-terminal` with
`AssertionError: 1 != 2`. The complete CI matrix has not passed; this release
is published manually and does not represent an all-green automated release.
