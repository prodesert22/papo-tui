- Added a native ARM64 Termux package for Android 9 and newer, using the terminal file picker and Termux runtime libraries; it includes the Unicode text segmentation library, so it installs from the standard Termux repository, and tapping a text field opens the on-screen keyboard.
- Fixed Flatpak package builds by bundling the display information library required for hardware-assisted video decoding.
- Arch packages now declare the certificate, font configuration and ALSA runtime dependencies needed for a complete installation.
- Fixed private library placement in packaged installations so DEB packages start correctly on clean systems.
- Added a manual script to generate and verify SHA256SUMS for local packages; release validation can regenerate an existing manifest.
- Added voice calls with GStreamer WebRTC and Opus, independent microphone/playback toggles below the signed-in name, and connected members with green speaker highlighting. Your own entry in the member list also turns green from the local microphone level while you transmit, even when the server leaves you out of its speaker ranking. Each connected member now also shows a microphone marker at the right of the name: **🎤** when open and a red **🎤×** when muted, replaced by **●** and **●×** on Light, Ultralight and text terminals, with no marker until the server reports that member's state. The signed-in name now has its own line in the sidebar with the audio, microphone and settings buttons below it, and the header shows only the focus. Builds without the GStreamer WebRTC stack, such as the Termux package, report that voice is unavailable and hide the call buttons.
- Added Audio settings for device selection, microphone and call volumes, a local playback test with colored level bars, and optional push-to-talk.
- Push-to-talk can now be bound to Ctrl or Alt combinations, function and navigation keys, Shift+Tab, or mouse buttons 4 and 5; the default is Ctrl+Y, lone modifier keys are ignored while capturing, and the Audio tab captures the combination directly with Esc cancelling without closing settings. Terminals that report key releases transmit while the key is held; terminals that only send the legacy Ctrl+letter control byte toggle the microphone on each press, with key repeats ignored, while Ctrl+number combinations require the extended keyboard protocol.
- Fixed history avatars, inline emoji and attachments disappearing while the Settings panel was open. Images outside the panel now stay visible and return when the panel closes.
- Reopening the application now restores every server you were signed in to as a tab in the top bar, instead of only the last one. The server you used last is selected and reopens the channel or direct message you had open; each server also returns to its own last conversation, including when you reopen the application with a single server. The other saved servers appear as tabs as soon as the sign-in screen opens, while their sessions are still being confirmed. If the selected server is unreachable, the sign-in screen keeps the tabs of the other servers at the top, so you can open them without signing in again. An unreachable server stays listed as **(offline)** with its saved session, and opening its tab again retries that session. Right-clicking a server tab, or pressing **m** on it, opens a menu below the tab with **Remover servidor** (Remove server); Delete on a selected tab goes straight to the confirmation. Removing a server takes it off the list and deletes its saved session after a confirmation. Signing out of a server forgets only that server's saved session, and a session saved by an earlier version still restores without signing in again.
- Fixed the realtime connection dropping about a minute after connecting on servers that expect WebSocket PONG replies, which showed "Desconectado · Reconectando…" and ended voice calls with "Chamada encerrada: conexão ou sessão interrompida".
- Sent messages now appear in the history at once and the editor clears immediately; a **enviando** (sending) tag at the right of the header disappears when the server confirms the message. A rejected message stays with **falhou** (failed) and an unconfirmed one with **não confirmado** (not confirmed); Ctrl+Y sends it again and replaces the entry instead of duplicating it. The text no longer waits in the editor until confirmation.
- Opening an old pinned message, search result or notification is faster: history requests now ask for 100 messages per page instead of the server's default of 30, and a notification whose message was not loaded yet starts the search at the notification time instead of going back page by page from the newest message.
- Fixed the help dialog leaving parts of itself on the sign-in screen after closing it.
- The server tab bar now sits on the top row of the conversation screen, at the same height as on the sign-in screen, without the border above it. On screens 80 columns or wider it uses a single row and the **Foco** (focus) label moved to the footer, to the left of **Ctrl+G: ajuda**; narrow screens keep the label next to the **[Canais]**/**[Conversa]** switch. Both give the history more rows.
- Fixed a server tab staying on **Conectando tempo real…** (connecting realtime) forever when it was opened after losing focus before its realtime connection finished, for example a saved server restored in the background. New messages only appeared after reopening the channel; the connection now opens as soon as the tab is shown again.
- Fixed the text cursor on the sign-in and add-server screen not blinking while other servers were connected. Their presence, typing and message events no longer repaint the form; it now only updates when a server tab changes.
- In 8- and 16-color terminals such as the Linux console (TTY), the border of the focused box now turns the accent color: the message editor's edges while typing and the line under the conversation header while the history has focus. These terminals cannot show the darker focus background, so the focused box looked the same as the others.
- Fixed images with transparent backgrounds (avatars, custom emoji, attachments and embed images) showing a dark gray box. Kitty and iTerm2 now receive the image with its transparency, so whatever is behind it shows through; Sixel and Chafa, which cannot show partial transparency, blend it into the actual background of the history, embed card, focused panel or selected item. A transparent avatar no longer reveals the author's initials underneath.
- Switching back to a channel or direct message you viewed recently on the same server, or to another server's tab, now shows it at once where you left it instead of reloading it. Up to eight conversations per server are kept. New messages that arrived meanwhile load on return when you were at the latest messages, or when you scroll down to them; edits, deletions, reactions, pins, a dropped realtime connection or **Ctrl+R** reload the conversation.
- Consecutive messages from the same author are no longer grouped under one header when more than an hour passed between them; the later message shows its own avatar, name and time.
- The message context menu has a new **Ver perfil** (View profile) option that opens the author's profile without opening the member drawer. It is not shown for messages sent by applications.
- Light mode now shows video covers and plays videos as colored characters, like images and animated GIFs.
- On terminals without Kitty, Sixel or iTerm2 graphics, such as the Linux console (TTY), the application now runs in Light, and Settings lists only Light, already marked, and Ultralight instead of offering Normal. A saved Normal preference is kept for other terminals.
- Fixed a saved server disappearing from the tabs after quitting the application while it was renewing that server's session, for example about 30 seconds after opening it. Quitting now waits up to five seconds for a renewal already in progress, so its new session is saved.
- Fixed conversations read in Papo TUI staying unread on the server, so their red dot came back after reopening the application and other devices still showed them as new. The server stopped counting a history load as a read; a conversation is now marked read when its latest message is visible at the bottom of the history, and opening it or scrolling through older messages no longer counts. A failed read is not retried automatically.
- Fixed the red unread dot appearing on startup for conversations you had already read: your own latest message, or a deleted last-read message, no longer marks a channel unread.
- Notifications for messages before the point where you read a conversation, in this client or another one, are now marked read with that read, so they leave the notification count and the badges instead of staying unread in the notification center.
- Fixed **Ctrl+R** sometimes doing nothing in a conversation when it was pressed while notifications, author names or a read were still loading in the background; the reload now runs as soon as that request finishes.
- Replies to your messages and `@everyone` messages are now highlighted in the history with the same colored bar as mentions of you, so every message that reaches the notification center stands out, whatever the channel's notification setting. Your own messages are no longer highlighted when they mention you.
- You can now select text in the conversation history by dragging with the mouse; it is copied to the clipboard as soon as you release the button. Dragging past the top or bottom of the history scrolls it to continue the selection, and another click clears it.
- The context menu of a voice channel now starts with **Abrir chat** (Open chat), which opens the channel's messages without joining the call.
- The **Notificações…** (Notifications) submenu of a channel has a new **Sincronizar com o servidor** (Sync with the server) option, checked by default. Unchecking it keeps that channel's notification option only on this device: later choices are not sent to the server and remain after restarting. Checking it again returns to the option saved on the server. Opening **Notificações…** now shows the option saved from another device without reopening the application, and the client also checks every five minutes; a device-only option changed in another window on the same computer appears within a second.
- Edited messages now show their new text in the history at once, and the editor returns to your send draft immediately instead of waiting for the server. An **editando** (editing) tag at the right of the header turns into **editado** (edited) when the server confirms, and a confirmed edit no longer reloads the conversation. If the edit is rejected or not confirmed, the message shows the server's text again and your text is kept: it returns to the editor when the send editor is empty, or the next edit of that message starts from it. Edits are still never retried automatically.
- Saving an edit after erasing all of its text now opens the **Excluir mensagem?** (Delete message?) confirmation instead of refusing the edit. **Excluir mensagem** deletes the message and closes editing; **Cancelar** or Esc returns to the edit.
- Fixed animated custom emoji, avatars and GIFs staying on their first frame when several of them were on screen, such as a message with many different animated emoji. Only the first two used to animate, and loading more media could also stop animations already playing.
- Audio attachments can now be played. They appear in the history as an inline player bar with `[▶]`, the file name and size, which shows the progress and a pause button while that audio plays in the background; they download only when opened, and open a player like the video one, with the embedded cover when the file has one, speed from 0.5× to 2× (`[`/`]`), repeat (`l`), restart with Space at the end and **[Parar]** (`x`). Esc keeps the audio playing in the background while you browse the server's channels and direct messages, with a mini-player in the footer to pause, stop or reopen it; **Ctrl+X** goes back to the audio's message and reopens its player without restarting it. Switching server tabs, signing out or changing the mode stops it. Sound files reported as a generic type are recognized by their extension, and Ultralight lists them as **Áudio**.
- Attachments that are not shown inline now appear as a file card with the file icon, name, size and a **[ ↓ ]** download button on the right, filled with the highlight color so it stands out from the card, replacing the plain **Anexo:** lines. Clicking the button, or choosing the new **Baixar anexo** item in a message's context menu (**Baixar anexos** when there are several), always asks where to save first: the system **Salvar anexo** dialog when a desktop is available, otherwise a terminal dialog to pick the folder and file name that warns before replacing an existing file. The file downloads in the background with progress in the footer, up to 512 MiB, and is written only once complete. Ultralight keeps the plain text listing.
- The message context menu now separates its options into four groups with horizontal lines: reactions (**Ver quem reagiu**, **Adicionar reação**), navigation (**Responder**, **Ir para mensagem original**), content (**Baixar anexo**, **Fixar mensagem**, **Ver perfil**) and actions on your own message (**Editar mensagem**, **Excluir mensagem**, now last and away from the other options). A group with no available option leaves no line, and clicking a line does nothing. **Ver perfil** is no longer the last option.
- On a message with three or more attachments, **Baixar anexos** in the context menu now opens a **Baixar anexos** list to choose which files to download, with a mark on each name and size, **A** to mark or unmark all, and **Cancelar**/**Baixar** buttons. Only the marked files are downloaded, each asking where to save. Messages with one or two attachments keep saving them directly.
- Fixed the media viewer only switching between images: videos and audios of the same message are now part of the sequence. On an image, ← and → move to the next or previous media, whatever its type; on a video or audio, where the arrows seek, **PageUp** and **PageDown** do it. The title of a video or audio shows its position, such as **2/3 · clip.mp4**, the captions list **PgUp/PgDn**, and the sequence wraps around.
- Fixed desktop notifications being silently lost when the notification service was unreachable or slow, which happened most often after the terminal had been unfocused for a long time. The notification is now retried for up to 15 seconds while the connection to the service is re-established, instead of being discarded.
- Fixed desktop notifications after the first one not appearing: each new message now raises its own notification instead of updating the previous one, which many notification services do silently when it was already shown or dismissed.
- Channels set to **all** notifications only on this device (not synced with the server) now raise desktop notifications for ordinary messages. Before, only messages the server already flagged produced them.
- Fixed desktop notifications for webhook messages showing **Autor indisponível** (author unavailable) as the sender; they now show the webhook's name, as the history does.
