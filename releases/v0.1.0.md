# Papo TUI 0.1.0

First release of the terminal chat client written in C17.

## Features

### Accounts and servers

- Registration with password confirmation, sign-in to public and private
  instances, session renewal and sign-out.
- Server profiles and tabs with sessions isolated by instance.
- Recovery of the last session through the system credential store, with server
  validation; manual sign-in remains available when no credential store is accessible.
- TLS verification and custom CA support through `CURL_CA_BUNDLE`.
- A global request budget and handling of server rate limits, without automatic
  retries of sends after HTTP 429.

### Conversations and notifications

- Text channels, starting DMs and text conversations in voice channels,
  accessible with F4 in the channel list.
- History paginated in both directions, with prefetching near the edges of the
  active conversation and a loading notice when reaching a pending page.
- Unicode text messages, a multiline editor and drafts for each conversation
  during the current run. Pasting preserves line breaks and does not send.
- Send confirmations reconciled between REST and WebSocket, preserving text
  edited while a message was being sent. Uncertain sends require confirmation
  before another attempt.
- Real-time messages, edits, deletions and embed updates;
  history reconciliation after reconnecting.
- Presence, typing indicators and unread messages. Read state is saved by
  server and account and reconciled with the backend on restart, without
  fetching histories of inactive conversations.
- Notification center and system notifications with preview preferences.
- User selection for mentions and highlighting in history; a searchable picker
  for Unicode and custom emojis.

### Interface and media

- Keyboard and mouse navigation, text selection and copying, editing by
  grapheme, resizing and a layout adapted to narrow screens.
- Footer shortcuts based on focus and a separate area for notices.
- Emoji suggestions triggered by `:`, filtered as you type and ordered by
  saved usage per account and instance. The F4 picker has labeled 32×32 previews
  and arrow navigation through search, source buttons and the grid.
- User and webhook avatars, application identification and grouping of
  consecutive messages, with edited messages kept separate.
- Image galleries that reflow with the available width, animated GIFs and
  embeds whose text and media update without reopening the conversation.
- Graphics rendering through Sixel, Kitty and iTerm2 protocols, depending on
  terminal support, and a media modal with audio and video playback.
- Videos scaled up or down proportionally to the player area, including
  sources with non-square pixels and resizing during paused playback.

## Fixes and performance

- Opening the emoji picker preserves images outside its bounds and reuses
  already decoded previews across redraws.

- Pagination preserves the reading position when fetching older or newer
  messages, including after slow responses and retries.
- Browsing the list or selecting the open conversation preserves history,
  drafts and the reading position, avoiding unnecessary requests.
- Shared image, emoji and avatar cache with deduplication, background work and
  memory limits. Avatars are reused during scrolling and idle periods; updates
  retain the previous image while a new version loads or if the request fails.
- Media libraries are loaded on demand, reducing startup overhead and the
  cost of text-only conversations.
- Fixed video playback in locales with a decimal comma while preserving UTF-8
  text support.
- Improved arrow-key focus, mouse events, pasting, mention alignment, colors
  and image redrawing without interrupting network processing.
- Fixed the display of webhook authors and messages without an available author.

## Distribution and maintenance

- Preparation of Linux x86_64/ARM64 builds as DEB for Debian and Ubuntu, RPM,
  `.pkg.tar.zst`, AppImage and Flatpak bundles.
- Preparation of native Windows x86_64/ARM64 builds as ZIP and an installer
  for the current user.
- Code organized by responsibility, platform adapters and modular CMake configuration.
- CI for builds, tests, formatting, static analysis and informational coverage
  reports, without a mandatory coverage threshold.
- HTTP tests with a mock backend and pseudoterminal interaction tests, including
  regressions for pagination, read cursors, avatars, video and Unicode editing.
- A publication workflow triggered by the `v0.1.0` tag or manually for an
  existing tag, after all artifacts have been validated.
- A simpler README and guides for [installation](../docs/installation.md),
  [usage](../docs/usage.md) and [builds](../docs/builds.md).

## Compatibility and limitations

The application version is independent of the API version. Earlier profile
formats remain readable; invalid configurations are preserved. Each instance
keeps its context isolated. Cookies remain in memory or in the system credential
store; passwords are never persisted. Recovery covers only the last active session.

Local read state does not synchronize other devices. Drafts and loaded history
are not persisted when the application closes.

Voice calls, uploads and reaction management are not part of this release;
voice channel support covers their text conversations.
Images and video require compatible graphics protocols; without them, chat
remains text-only. Changes outside the retrieved history window require another
request; complete replay of server events is not guaranteed.

## Installation and updates

Choose the asset for your operating system and architecture from the release.
Check `SHA256SUMS`. Separate DEB builds are provided for Debian and Ubuntu.
Install the complete package, including modules and libraries.

The ZIP runs without installation; the Windows installer and Linux package
managers preserve user data during updates and removal. Flatpak builds have
their own data directory. Sign out before removing the application if you want
to invalidate persistent session recovery.

The corresponding source code for bundled libraries and their build options
accompany the artifacts. Original code uses MIT; third-party components retain
their licenses. Local validation of one package does not replace CI validation
of other systems and architectures.
